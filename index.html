NEXA — Bilingual Enterprise Operations Agent

2026

An employee asks a question in Arabic and gets the answer out of an English policy document. A manager asks to change a project's status, and the system refuses to run it until a director approves. NEXA is built on one rule: a prompt is a request, code is a guarantee. Permissions are checked in the tool execution layer, identity comes only from a validated token, and no sensitive action executes without a persisted human approval — regardless of what any prompt, retrieved document, or model output says.

InputA question in Arabic or English, or a request to change project state
→
ProcessMultilingual dense retrieval with cross-encoder reranking; enum-typed tool layer with role checks and a human approval gate
→
OutputA cited cross-lingual answer, or an approved state change written with its audit record
Cross-lingual retrieval · 12 documents, 24 questions, answer never in the query's language
Pipeline Recall@1 Same-language bias
Dense retrieval only 0.38 0.62
Dense + cross-encoder rerank 0.92 0.08

Recall@5 under dense retrieval alone was already 0.92 — the right document was being found, just not ranked first. Same-language bias measures how often the top result shares the query's language, where 0.50 is neutral. Reranking is what closed the gap.

An Arabic query returning an English source
Retrieval, authentication, the tool layer, and the approval flow are built, measured, and covered by 71 tests. The LangGraph agent that orchestrates the tools is specified and in progress. All data in the repository is synthetic.

Bilingual RAG Chatbot — PSAU Student Assistant

2026

Students ask the same questions every semester — admissions, policies, study plans, deadlines — and the answers sit buried in documents nobody reads. This assistant answers them conversationally in Arabic or English, retrieving from a curated set of 80 university documents so every answer is grounded in real policy instead of an invented one. Co-built in a team of four; I worked on the retrieval side.

InputStudent question, Arabic or English
→
ProcessHybrid retrieval — BM25 keyword search fused with multilingual dense embeddings in FAISS via Reciprocal Rank Fusion
→
OutputA cited answer generated under a strict grounding prompt, restricted to retrieved context
0.762 → 0.857 Arabic retrieval MRR, after query normalization and a bilingual academic glossary
100% Recall@3 in both languages — the correct source always reaches the model
< 1s Cited answer returned, via Llama 3.3 70B on the Groq API

Arabic retrieval was the hard part: matching how a student actually phrases a question to how a policy document formally states it.
